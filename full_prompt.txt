# 10. Important Cross-Application Workflows

The frontend must demonstrate how the different applications work together.

### Workflow A – Employee Onboarding

HR registers an employee → collects documents → simulates eKYC → HR approves → Employee ID generated → ID card preview generated → employee becomes available in Operations.

### Workflow B – Workforce Deployment

Operations selects an HR-approved employee → selects client → selects site → assigns designation → assigns supervisor → assigns shift → confirms deployment.

The employee should now appear in the Employee App's assigned-site and shift screens.

### Workflow C – Attendance

Employee opens app → taps Punch In → simulated GPS verification → attendance status updated in the demo state.

The attendance information should reflect consistently in:

- Super Admin attendance.
- HR attendance.
- Operations attendance.
- Client attendance.

### Workflow D – Client Visibility

Operations deploys employees to a site → employee attendance changes → client dashboard reflects the corresponding workforce and attendance status.

### Workflow E – ID Card

HR approves employee → unique employee ID is displayed → ID card preview becomes available.

These workflows must be demonstrable using shared mock data and local frontend state.
